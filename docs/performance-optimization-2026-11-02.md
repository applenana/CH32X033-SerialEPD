# 色彩映射性能优化记录

本次优化面向所有运行端，手机端只是更容易暴露同一计算瓶颈。

## 变更

- 固定四色调色板只建立一次 4×4 逆矩阵。重建过程不再为每个像素重复做高斯消元；AUTO 的原图分析也复用同一个 `PaletteProjector`。
- `processPrepared` 的每像素颜色调整改为标量局部变量，避免创建临时 RGB 列表和对应的垃圾回收压力。
- 面板分辨率的感知 DBS 使用一轮邻域优化；小图仍保留三轮。蓝噪声和直接量化路径不改变算法结果。
- 图像计算继续运行在 Flutter 后台 isolate，界面线程不会承担映射计算。

## 软件测量

使用 `app/tool/benchmark_mapping.dart` 对 768×552 输入进行 Dart 发布前运行时测量。相同输入的基线与优化后输出色号计数一致：

| 阶段 | 基线 | 优化后 |
| --- | ---: | ---: |
| 蓝噪声重建 | 579 ms | 321 ms |
| 感知重建 | 1,016 ms | 752 ms |
| 完整默认处理 | 1,085 ms | 774 ms |

这些是当前 Windows 环境的 Dart 运行时数据，不等同于具体手机型号的实测。手机仍需要安装 APK 后用同一图片和参数读取界面耗时；真实墨水屏刷新时间也不包含在上述数字中。

## 2026-11-03 底层热路径优化复测

本轮没有继续增加 isolate 并行：Release/AOT 实测显示，把相关通道拆到多个 isolate 会因大块像素数据复制而变慢。改为所有平台共用的纯 Dart 热路径优化：

- 线性光转换和 OKLab 立方根使用 16384 项查表，避免每像素重复 `pow`；
- 扩散误差使用标量局部值，避免每像素创建 RGB 临时列表；
- 色域投影预计算调色板亮度，并移除热循环中的列表生成和归约；
- 相关卷积预计算边界范围，减少每像素边界函数调用。

Release/AOT 同一台 Windows 主机、768×552 内置示例，优化前后中位耗时如下。输出色号仍通过现有 Flutter 测试和回归测试。

| 模式 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 直接量化 | 123 ms | 104 ms |
| Floyd–Steinberg | 190 ms | 170 ms |
| Stucki | 264 ms | 241 ms |
| Burkes | 220 ms | 199 ms |
| 蓝噪声 | 282 ms | 218 ms |
| 感知 DBS | 534 ms | 462 ms |

## 2026-11-03 缓存与统一热路径复测

把与算法无关的颜色调整结果缓存到常驻处理 isolate，并让所有算法复用同一份调整后源图；同时使用标量调色板距离、sRGB 反变换查表和 Float32 工作缓冲。Windows AOT 同一输入的当前测量为：

| 模式 | 当前中位耗时 |
| --- | ---: |
| 直接量化 | 42 ms |
| Floyd–Steinberg | 108 ms |
| Stucki | 176 ms |
| Burkes | 135 ms |
| 蓝噪声 | 156 ms |
| 感知 DBS | 402 ms |

这些数字来自独立 benchmark 的处理阶段，仍不包括应用启动、首帧、文件选择器和实体墨水屏刷新。多 isolate 拆分 DBS 卷积在相同机器上实测约 650–690 ms，慢于单 isolate 约 570–600 ms，因此没有保留这种跨平台实现；大块像素在 isolate 之间传输的成本超过了并行收益。

这些数字是图像处理阶段，不含应用进程启动、Flutter 首帧、文件选择器和实体墨水屏刷新。查表使用有限精度近似，端点保持精确；如需实体面板级复核，应重新检查代表性照片、文字和纯色区域。
