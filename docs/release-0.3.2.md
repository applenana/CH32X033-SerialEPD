# Ink Studio 0.3.2 · 自然映射

2026-10-28。按用户要求只修改与编译，不执行测试、静态分析、图像评分、UI 或实屏验证；效果是否更自然由用户对比。既有 0.3.0 指标不能作为本版效果提升的证据。

## 借鉴与实现

参考 `wiwiwei/ink-nfc-lab` 的 `ResearchQuantizer.java`：低彩度 / 冷色平滑去色、最近色选择时抑制不合适的红黄候选。Ink Studio 自行实现 `app/lib/imaging/color_mapping.dart`，未移植 Java 源码。公式阈值是可调启发式处理，不是实屏标定结果。

1. 在缩放、亮度、对比度、饱和度和 Gamma 后，根据尚未受抖动误差影响的源像素生成固定掩码。sRGB 通道差使用 smoothstep（0.015–0.16）估计彩度，再以蓝相对红及绿红加权值的优势估计冷色程度。两个平滑权重相乘得到适合使用红黄墨色的程度。
2. 保护量 `p = 自然映射强度 × (1 − 墨色适合度)`。将颜色解码到线性 RGB，计算 `Y = 0.2126R + 0.7152G + 0.0722B`，按 `C' = Y + (C − Y)(1 − p)` 平滑趋近同亮度灰色，再编码回 sRGB。该凸组合不越出 RGB 范围，预处理的线性亮度保持不变（浮点 / 查表精度除外）。纯黑白、饱和红黄保持原值。后续量化与网点采样不承诺逐像素亮度不变。
3. DBS 和蓝噪声对映射后的颜色执行已有覆盖率投影。DBS 仍只交换网点，因此保持的是**新映射目标**初始分配的四色数量，并非旧版图像的数量。
4. 三种传统扩散及直接量化按掩码给红黄候选增加 `0.25p` 的距离惩罚。开启自然映射时，严格中性灰只选黑白，避免邻居误差造成灰区彩点。扩散误差进入邻居前，按邻居保护量压低其色度分量，保留编码 RGB 加权亮度误差。这一部分仍是传统 gamma 编码 RGB 误差扩散，不宣称全程线性光处理。

直接沿用对方较暗的红黄调色板，会与当前理想四色覆盖率公式和预览假设不一致；本版保留原调色板。若以后加入实测调色板，需要同步处理覆盖率分解、最近色、DBS 目标与预览。

## 操作与取舍

- “自然映射”滑块范围 0–1。默认及照片预设 0.65；插画 0.35；文字 0。强度为 0 时完全绕过新增预处理、惩罚与扩散保护，可和旧路径对比。
- 偏好保存包含该强度；旧配置缺少字段时补为 0.65，原有其它参数保留。照片 / 插画 / 文字预设会重新设定相应强度。
- 减少红黄杂点可能损失低彩度差异，蓝青区域更接近灰色。它无法产生实体蓝绿墨色，也没有增加原生灰阶；最终仍使用 SEP/1 四色 2bpp 帧。
- 保持三种传统抖动和现有两种重建、直接量化，总共六项，不增加重复算法菜单。

## 本机使用

默认只编译，不再生成 ZIP 或复制发布包。Windows 直接运行 `app/build/windows/x64/runner/Release/ink_studio.exe`，保留其同目录依赖；Android 使用 `app/build/app/outputs/apk/release/app-release.apk`。APK 仍是开发证书签名的 Release 构建。

建议用户用同一图片固定其它设置，将自然映射从 0 调至 0.65 比较灰墙、天空、肤色、浅色衣物和暖色渐变。需亲自确认是否符合实际面板和观看距离；本轮没有宣称验证通过。
